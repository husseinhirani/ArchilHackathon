StegoArena in 60 seconds

Steganography is hiding a secret inside an ordinary file. StegoArena turns it into a game between AIs:

  1. A hider AI hides a secret flag in an image. It chooses how: which pixels and bits, scrambled or not, encrypted or not, where the key lives, and whether to plant a decoy.
  2. Finder AIs hunt for it blind. Each attempt runs inside its own Archil sandbox, a cloud machine forked in about 2 seconds from a template with every stego tool installed. It gets 90 seconds and can search the web with Keenable.
  3. Both sides learn and evolve. After each round the answers are revealed. Finders rewrite their own playbook and keep tools they coded; hiders study what got cracked. The weakest agents are replaced by mutated children of the best.
The claim: agents get measurably better at finding and hiding without upgrading the model. Every agent uses the same Claude model and effort setting; only their experience differs.

Reading the Lab, top to bottom

  1. How it works (three cards). The game in three steps, each with a live number: images hidden, attempts run with average sandbox fork time, and the current generation with the locked model.
  2. The result. The headline number: crack rate on a held-out set of puzzles no agent ever trained on, for the bare model ("static") vs the best evolved agent, same model. The bar chart shows every evaluation run.
  3. Watch a highlight. Pre-picked great moments: fastest crack, a branch that won, a web search that changed the next command, a dodged decoy, a tool the agent wrote and kept, and the hider's toughest survivor. Click one; the replay opens at that moment.
  4. Rounds. Tabs per round or generation. Each card is one image with a secret, shown with:
    • a ✓ cracked or 🛡 survived badge and an Easy/Medium/Hard level;
    • a plain-English description of how it was hidden, plus the hider's own reasoning;
    • finder pills: one per attempt (✓/✗, time or score, 🔀 if it branched, 🔎 if it searched). Click a pill to replay it.
    If the hiders researched on Keenable before designing, their queries show above the cards.
  5. Replay. The attempt, step by step (see the next section). A summary bar shows time used, commands run, searches, branches and tools saved.
  6. The agents' minds. Every finder and hider. Click a finder to read its playbook (rules it wrote for itself), its toolkit (code it wrote, viewable), and what it learned each generation. Retired agents are faded.
  7. Elo ladder. Who's winning the arms race. Finder ratings over time, with scheme ratings as dots.

Hover or tab to any i for a one-line definition. The page refreshes itself every 20 seconds, so you can leave it open while a run is going.

Reading a replay

Use Play to auto-advance, Step for one event at a time, Show all to dump the rest, and ⭐ Jump to key moment when you came from a highlight.

Branch lanes

When a finder calls branch, Archil live-forks its running sandbox, memory and all, once per hypothesis. Each branch's events are indented and dashed, with a tag like b0:dct. The first branch to extract the flag stops the others, and the original agent gets every branch's findings.

"Informed by Keenable"

When a tool shows something not in the agent's playbook, it's flagged as ❓ unfamiliar. If the agent then searches the web, the next command it runs shows 🔎 informed by Keenable: "…", so you can see exactly how the search changed what it did. As the playbook learns a signal, it stops being flagged.

A 3-minute demo path for judges

  1. Live → upload a judge's photo → Fair fight → Start. Watch the hider search Keenable, read the top finder's playbook and design a scheme. Then watch 4 finders race in parallel sandboxes. Point at the "difference ×64" image: the secret is invisible to the eye. (90s)
  2. Lab → The result. Read the headline: same model, higher crack rate after evolving. (30s)
  3. Lab → Watch a highlight → "Parallel hypotheses". Watch the live fork and the winning branch. (45s)
  4. Lab → Watch a highlight → "A web search changed its next move". Show the ❓ → 🔎 → informed command chain. (30s)
  5. Lab → The agents' minds → click the top finder. Read two playbook rules it wrote and open one tool it coded. (30s)
  6. Optional, Hide & Seek. A judge hides a sentence and races the AI themselves. (45s)

Run it yourself

Needs Python 3.11+ and uv. Copy .env.example to .env and add keys. Without keys it falls back to a local sandbox, a scripted finder and offline search.

Start the site

uv sync uv run stegoarena ui # http://127.0.0.1:8000

Check the plumbing

uv run stegoarena template --provider archil # build the tool-loaded sandbox template (~30s) uv run stegoarena smoke --provider archil # an easy image must be cracked in a fork

Hide & Seek from the terminal

uv run stegoarena hide -m "meet me at the fountain" --level medium --hint "check the metadata"

Grow and measure the agents

uv run stegoarena eval-set --n 6 uv run stegoarena eval --genome static --repeats 2 # the bare model uv run stegoarena evolve --generations 3 # learn, branch, research, select uv run stegoarena eval --genome champion --repeats 2 # same model, evolved mind

FAQ

Isn't this just a bigger model?

No. The model and effort are locked for the whole run; the evolve command refuses to continue if they change. The headline compares the bare model with evolved agents on puzzles none of them trained on.

Can the hider cheat with an unbreakable key?

No. A solvability gate bans unrecoverable keys, so every scheme is crackable in principle. Hiders win by being subtle, not impossible.

What does Archil do here?

Each attempt is a fork of one template sandbox with every stego tool installed: about 2 seconds, isolated, run many at once. Finders can also live-fork mid-attempt to try ideas in parallel. Every trace is mirrored to an Archil disk, so any crack can be replayed.

What does Keenable do here?

Hiders research detection methods before each generation; finders search when they meet a signal they don't recognise. Both are shown in the replay.

Is the replay live?

The Lab replays recorded runs from disk, so it works offline. Live and Hide & Seek matches run for real while you watch.

Fair fight vs All out?

In a Fair fight the hider must keep the key findable within 90 seconds (metadata or wordlist), so you get a real race. All out lets it use ~16k-key biglists; usually nobody cracks it, which shows how strong the hider has become.
